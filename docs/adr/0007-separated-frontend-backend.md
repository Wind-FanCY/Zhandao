# 前后端分离：Vite + React + Express，不用一体化框架

Web 界面与 API 拆成两个进程：前端 Vite + React，后端 Express。2026 年做 React 全栈项目的常规选择是一体化框架（Next.js / SvelteKit），此处刻意偏离。原因是本项目的目的之一是**学习全栈开发**，而分离式让客户端与服务端之间的接缝全部保持可见——路由、数据获取、CORS、序列化边界都得自己写一遍；一体化框架会把这些收进约定里。

## Considered Options

- **Next.js（App Router）**：一条命令启动，服务端逻辑与页面同进程，就业相关性最高。被否的唯一理由是它把接缝藏进约定，与学习目的冲突。
- **SvelteKit**：同样一体化，更轻，但生态与就业相关性都小一圈。
- **Vite + React + Express**（已选）。

## Consequences

- **启动需要起两个进程**，而 ADR-0002 把"本人会不会打开它"列为存亡问题。因此必须用单条 `npm run dev` 同时拉起前后端；接缝仍在代码里，只是启动命令统一。
- 需自行处理 CORS、前后端端口、开发代理。这既是成本，也正是学习目标本身。
- 前端是 SPA，无服务端渲染。对个人本地工具无影响：不需要 SEO，首屏延迟可接受。
- launchd 定时脚本（ADR-0004）直接调后端或独立脚本，不依赖前端。
- **不要把此项"修正"成 Next.js。** 将来若有人（包括本人）提议迁移到一体化框架，先读本 ADR——接缝可见是刻意选择，不是技术债。
