# 标注独立成文件，身份存在 frontmatter 而非文件名

一条**标注**是自己的一个 Markdown 文件，不是**材料**文件里的一段。原因是已有两条决定要求**标注**可被稳定寻址：**关联**可以指向一条**标注**（ADR-0001），**答题记录**挂在**标注**上（CONTEXT.md）。嵌在文件里的一段文字没有天然标识——只能靠行号、标题或偏移量之类的文件内锚点，而正文一改锚点就漂移，指向全断；**标注**不可再生，指向断了即资产损坏。

进一步地，标识写在 frontmatter 的 `id` 字段里，**文件名只是给人看的装饰，不参与解析**。重命名因此永远安全。

## Considered Options

- **嵌在材料文件里**（正文后追加或 frontmatter 数组）：文件数少，但无稳定标识，且需要一个"从材料文件里切出标注"的解析器——每次手改格式都可能崩。
- **同文件内加结构化分隔符与 ID**：认真的折中，但要自己实现 ID 分配与文件内解析，把文件系统白送的能力重写一遍，换来的只是文件数变少；文件数不是瓶颈。
- **独立文件**（已选）。

## Consequences

- 切块规则「**标注**一条一块」由文件边界天然满足，无需解析器（见 CLAUDE.md 技术路线）。
- `git log` 中"新增一条**标注**"是一次干净的提交，ADR-0003 指望的"用 git log 回溯理解演变"由此成立。
- 一份**材料**加五条**标注**等于六个文件，目录比"一材料一文件"碎得多。
- 读一份**材料**时需把它的**标注**聚合起来展示，必须走索引——但 ADR-0003 已定必须有派生索引，故非新增成本。
- 因标识不在文件名里，`id` → 文件路径的映射必须由索引维护；索引损坏时需全盘重扫恢复。
- **关联**无需为每个指向单独记理由：理由就是该条**标注**的正文本身（ADR-0001 已定"没有标注就没有关联"）。因此 frontmatter 里只存指向目标的 id 列表。
