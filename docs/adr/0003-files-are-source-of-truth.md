# 文件是真相源，数据库只存派生物

**材料**与**标注**以 Markdown + frontmatter 落盘；检索索引、向量与关联的反向查询副本存入 SQLite，且全部可从文件重建。依据是一条原则：不可再生的数据用最笨、最不锁定的格式存，可再生的数据扔进数据库，坏了删掉重建即可。**标注**不可再生，是本项目唯一不可替代的资产；**关联**由**标注**承载（见 ADR-0001），因而也落在文件里，不需要独立存储。

## Considered Options

- **全进数据库**：查询最直接，但数据锁在库内，改 schema 要写迁移，备份要 dump，无法用编辑器直接改一条**标注**。
- **全是文件**：不锁定，但 BM25、向量检索、孤岛查询全部退化为全扫。
- **文件为真相源 + 数据库为派生索引**（已选）。

## Consequences

- 备份即备份一个目录；纳入 git 后，**标注**的版本史白送——理解的演变过程可用 `git log` 回溯。
- schema 可随意变更，无需迁移脚本：删库重建即可。
- 启动需扫描文件重建索引。数百份**材料**的量级下开销可忽略；量级上去后需要增量索引。
- 反向查询（"哪些**标注**指向这份**材料**"、"哪些是孤岛"）必须走索引，不能直接读文件。
- 派生库选用 SQLite 而非 Postgres：它承担的是可重建的索引角色，不涉及 schema 设计、事务边界、连接池等真正需要 Postgres 的场景，且自带 FTS5、零运维。该选择易于更换，不构成锁定，故不单独立项。
