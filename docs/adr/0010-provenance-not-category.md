# 材料记来源（`from`），但来源不是分类、更不是关联

**索引页**（只含目录与元信息的页面）本身不成为**材料**——它没有内容，按 CONTEXT.md 的定义就不够格。它的价值在于展开出多份**材料**，而每份展开出来的**材料**在 frontmatter 里用 `from` 记下是哪个**索引页**展开了它。

**材料的粒度是站点作者切好的那一节，不合并。** 实测依据：`xiaolincoding.com/network/` 展开出 41 节，落在 5 个路径段里，其中 `3_tcp` 一段就有 24 节（「三次握手」到「tcp_tw_reuse 为什么默认关闭」）。这些是不同的内容，只是同一主题。而小林那套每节几千字，24 节合并约几万字——立刻把我们刚绕开的切块问题请回来（对照：库里 42807 字符的那份材料按 h2 只能切出 39700 字符的巨块，命中它等于「这篇里有相关内容」，零定位价值）。

## 为什么这不违反 ADR-0001

ADR-0001 拒绝「知识点」实体，理由是两条：**粒度摇摆**（React / useEffect / 依赖数组该选哪级）与**分类摩擦**（每次收录都要本人决定归属）。对 `from` 这两条都不成立：

```
分类（被拒绝的）   「这篇是关于网络的」        判断、粒度不稳、要本人决定
来源（本条采用的） 「这篇是从那个索引页展开的」  事实、唯一确定、系统自动记
```

一份**材料**只可能从一个地方展开。系统知道，本人不用做任何判断。

**「篇」这一层不存字段**：它可以从 `source` 的 URL 路径算出来（`/network/3_tcp/...`）。这正是 ADR-0001 说的「分类从数据算出来，不预先存」。

## Consequences

- **`from` 绝不算作关联，不进图谱。** 这是硬线。一旦把「同一 `from`」当成连线，ADR-0001 定的孤岛检测立刻失效：41 份**材料**瞬间全部「已连接」，而本人一篇都没读过——唯一的健康度指标就废了。
  `from` 是分组（事实，自动），**关联**是判断（本人确认，且必须带理由＝**标注**正文）。
- **接受一个洞：系列级的洞察没地方挂。** 若本人的理解是关于整个系列而非某一节的，**索引页**已不是**材料**，故无宿主可挂（而 Q10 定了**标注**必须有宿主）。判断是这类想法很少见——**这是推测，没有数据**。若实际经常发生，本条需重议。
- **批量收录会让孤岛数暴增**，收 41 节、标注 3 节就是 38 个孤岛。这不是指标坏了，是真相：那 38 节确实没被消化。要提前知道，否则看到数字会误判。
- 同一系列的**材料**词汇高度重合，检索会把它们一起返回，候选列表区分度低。缓解在呈现层：候选里显示 `from`，一眼看出是同一系列的若干节。
- 已收录的 6 份没有 `from`。那三篇掘金的系列关系（「前端面试刷题必备」性能优化篇与手撕代码篇确实是一个系列）补不回来，除非手填。
- **URL 前缀不能替代 `from`**：`xiaolincoding.com/network/*` 靠前缀能分组，但掘金是 `juejin.cn/post/<纯数字ID>`，路径无结构——库里现有的 6 份上这个方案就已经失效。
