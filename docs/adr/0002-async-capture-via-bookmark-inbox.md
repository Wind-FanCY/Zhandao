# 收录是异步的，经由浏览器书签收件箱

本项目只在本地运行，由本人按需启动；而判定一份内容"值得留"的时刻发生在浏览器里读文章时，那时服务多半没开。因此**收录**不做成同步动作（bookmarklet、浏览器扩展都要求服务在线），而是两段式：读到值得留的东西时存进一个专用的浏览器书签夹，服务启动后再批量抓取、逐条过闸，留下的成为**材料**。

## Considered Options

- **部署到公网服务器**：可随时同步收录，但引入鉴权、备份、持续成本，且违背个人知识库的本地优先常规。已否决。
- **Bookmarklet / 浏览器扩展**：摩擦最低，但都要求服务在线，在本地按需启动的前提下不成立。
- **纯文本收件箱**（`inbox.md` 一行一链接）：更笨、更可控、不依赖浏览器格式，作为退路保留。
- **书签夹收件箱**（已选）：浏览器原生，`Ctrl+D` 是既有肌肉记忆，零新技术。

## Consequences

- 收录与"服务是否运行"完全解耦，这是本地按需启动方案能成立的前提。
- "值得留吗"的判断从读完当下推迟到批量过闸时——判断质量更高，因为脱离了刚读完的兴奋。
- 引入了本项目最主要的失效模式：**收件箱堆积**。积到几十条后本人将不再处理，收录随之停摆。缓解手段（限制单次呈现条数、过期提醒）属于后续工作，但这个风险必须被持续盯着。
- 依赖浏览器书签文件的格式。格式变更会打断收录，故保留纯文本收件箱作为退路。
