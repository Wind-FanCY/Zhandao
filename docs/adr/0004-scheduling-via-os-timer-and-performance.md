# 复习调度：系统定时任务触发，依据答题表现而非通用遗忘曲线

复习需要外部触发，否则退化为"你想起来才去看"——而想不起来的东西正是最需要复习的。但服务按需启动（ADR-0002），没有常驻进程可发起推送。因此由操作系统的定时任务（macOS launchd）到点唤醒一个小脚本：它读**答题记录**、算出到期的**标注**、发一条系统通知，然后退出；本人点击通知才拉起主服务。调度依据是本人自己的答题表现——答砸的**标注**提前重推，答得利索的往后排——而非通用的艾宾浩斯间隔。

## Considered Options

- **启动时结算**：完全自洽、零成本，但没有外部触发，等于承认该功能作废。
- **常驻后台进程**：真推送，但与按需启动直接冲突。
- **外部渠道**（邮件 / Telegram）：需要本人关机时仍在运行的东西，绕回已否决的部署方案。
- **系统定时任务**（已选）：不常驻，每次跑几百毫秒，不碰模型、不起 Web 服务。

## Consequences

- 与 ADR-0002 不冲突：其核心约束是"**收录**不能依赖服务在线"，而非"不得存在任何定时任务"。**收录**仍走书签**收件箱**，主服务仍按需启动。
- 机器关机时收不到通知。定时设在本人通常在电脑前的时段，不追求必达。
- 间隔重复本质是背诵工具，针对离散事实；本项目的**标注**是理解类知识，套用通用遗忘曲线属工具错配，故弃用。
- **答题记录**（ADR 外，见 CONTEXT.md）成为调度的唯一信号源，不再引入额外机制。这也意味着：在产生第一批**答题记录**之前，调度没有依据可用。
- 引入了对 macOS launchd 的平台依赖。换平台需重写触发层，但该层与主服务解耦，代价局限在一个脚本内。
