# 数据与代码分仓：两个 git 仓库

**材料**与**标注**放在独立的 git 仓库，与代码仓库分离。ADR-0003 把「用 `git log` 回溯理解的演变」列为一项收益，而代码与数据的生命周期完全不同——代码会被重构和推翻重写，**标注**只追加且必须永久保留。混在一条历史里，两边都变得不可读，那项收益随之作废。此外**材料**是抓取的第三方正文，数据仓库必须保持私有；分仓之后代码仓库才可以自由开源。

## Considered Options

- **单仓库**：管理最简单，但历史混杂，且整个仓库被迫私有。
- **只有代码进 git，数据不版本化**：违背 ADR-0003——**标注**不可再生，不版本化等于把本项目唯一不可替代的资产裸放在磁盘上。
- **双仓库**（已选）。

## Consequences

- 具体布局：`Zhandao/` 只是容器目录、本身不是仓库；`Zhandao/code/` 与 `Zhandao/data/` 平级，各自是独立 git 仓库。数据不在代码仓库内部，故无嵌套仓库问题。数据根路径由环境变量配置。
- **数据仓库不得推送到公开托管。** **材料**是第三方正文，个人自用属合理范围，公开分发不是。
- 两个仓库需分别提交、分别备份。
- SQLite 派生库两个仓库都不进：ADR-0003 已定其随时可删可重建，进 git 纯属污染历史。
- 应用必须支持可配置的数据根路径，不得硬编码相对路径。这同时让"本地开发与真实数据分离"成为可能——ADR-0002 的本地按需启动方案下，这是唯一的环境隔离手段。
