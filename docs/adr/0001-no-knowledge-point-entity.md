# 不设「知识点」实体

知识库通常引入「知识点」作为枢纽实体，让多份材料与多条标注挂靠其上。本项目不这么做：模型里只有**材料**、**标注**，以及它们之间经确认的**关联**；任何分类在需要时从关联图计算得出，不预先存储。理由是「知识点」在本项目中没有独占职责——题目单位由标注承担，关联由确认过的直连边承担，图谱节点由内容本身承担——而它会给收录和标注引入分类负担，这两个动作必须零摩擦，否则库会一直空着。

## Considered Options

- **独立实体**：结构最强，哪怕一条标注没写也有骨架。但每次收录/标注都要决定归属，且粒度（React / useEffect / useEffect 的依赖数组）无法长期稳定。
- **标签**：成本低，但规模上去后近义标签（react / React / 前端）失控。
- **不设**（已选）。

## Consequences

- 切块策略随之确定：材料按标题层级切，标注一条一块，且标注必须与其附着的材料块一同进入检索结果。
- 图谱节点是材料与标注本身，数量远大于知识点方案，需要折叠或过滤才可读。
- "我在哪个领域最深"这类问题由聚类算出，而非直接查询。
- 若标注稀少，关联图退化为孤岛，聚合全部失效——但这与项目本身的失败条件重合，不构成额外风险。
